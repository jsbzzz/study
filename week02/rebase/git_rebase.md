
- ## AI정리
  - ### Git Rebase의 단계별 동작 원리와 충돌 해결
    - git rebase는 현재 브랜치가 파생된 기준점을 대상 브랜치의 최신 커밋으로 재설정하는 강력한 명령어입니다.  
    - 🔄 Rebase는 실제로 어떻게 동작하는가?  
      1. **공통 조상 찾기**: 현재 브랜치와 대상 브랜치가 갈라져 나온 최초의 분기점(조상 커밋)을 찾습니다.  
      2. **작업물 임시 보관**: 공통 조상 이후에 현재 브랜치에만 추가된 커밋들을 잠시 복사하여 임시 공간에 보관합니다.  
      3. **기준점(Base) 이동**: 현재 브랜치의 위치를 대상 브랜치의 최신 커밋으로 옮깁니다.  
      4. **커밋 이어 붙이기**: 임시 공간에 보관했던 커밋들을 대상 브랜치의 최신 커밋 위에 하나씩 순서대로 다시 이어 붙입니다.  
    - 💥 충돌(Conflict) 발생과 해결 방법  
      - 커밋을 하나씩 다시 얹어놓는 과정이므로, 대상 브랜치와 수정 내용이 겹치면 충돌이 일어날 수 있습니다. 충돌 발생 시 Git은 Rebase 과정을 일시 정지합니다.  
      - **해결 후 계속 진행 (정석)**: 충돌이 발생한 파일을 열어 코드를 올바르게 수정한 후, git add 명령어로 다시 Staging Area에 올립니다. 그 후 git rebase --continue를 입력하여 남은 과정을 계속 진행합니다.  
      - **현재 커밋 건너뛰기**: 만약 해당 커밋의 수정 내역을 아예 적용하지 않고 버리려면 git rebase --skip을 입력합니다.  
      - **위급 상황 (전면 취소)**: Rebase 과정이 너무 꼬여서 처음 상태로 되돌리고 싶다면 git rebase --abort를 입력하여 Rebase 자체를 취소합니다.  
    - 🎯 Rebase의 필수 마무리 작업 (Fast-Forward)  
      - Rebase가 성공적으로 끝났다고 해서 모든 작업이 완료된 것은 아닙니다. Rebase를 통해 이동한 것은 '현재 브랜치'뿐이므로, 대상 브랜치의 팁(Tip)은 여전히 과거의 제자리에 머물러 있습니다.  
      - **최신화(동기화)**: 대상 브랜치로 이동(checkout/switch)한 후 merge를 실행해야 합니다. 이렇게 하면 Fast-Forward merge가 발생하여 분기된 흔적이 남지 않고 깔끔한 일직선 히스토리가 완성됩니다.  
      - **주의 사항**: 만약 대상 브랜치로 이동 후 merge하지 않고 대상 브랜치에서 곧바로 새로운 커밋을 생성해 버리면, 기껏 일직선으로 만들었던 브랜치가 해당 위치부터 다시 분기되므로 주의해야 합니다.
